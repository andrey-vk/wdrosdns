Расширение Edge/Chrome (Manifest V3) для добавления доменов текущей страницы и доменов из
сетевых запросов в статические DNS-записи MikroTik RouterOS через REST API RouterOS.

## Основные возможности

### Всплывающее окно (popup)

- Панель приложения с индикатором соединения: при открытии popup роутер опрашивается
  автоматически.
- Выбор профиля (автоопределение и все сохранённые профили) через стрелку в панели
  приложения.
- Поле домена с переключателем `Domain / Host`, который переписывает значение на месте.
- Строка чипов, точно показывающая, что будет создано — тип записи и цель, `match-subdomain`,
  `address-list`, сервер `:resolve` — и открывающая страницу настроек по клику.
- Дополнительные домены скрыты под раскрывающимся блоком.
- Сборщик сетевых доменов:
  - собирает запросы по текущему `tabId`;
  - группирует домены по host/base-host с бейджами HTTP-статуса и ошибок;
  - поле поиска, всплывающее окно фильтров (включая `show all`), выбрать все/снять выбор,
    счётчик выбранного;
  - одно основное действие (добавить выбранное) с `add shown` / `add all captured` в меню.
- Блок результата: по одной строке на домен с результатом добавления и `:resolve`, а также
  необработанный ответ роутера под раскрывающимся блоком.

### Страница настроек

Правая панель объединяет `Global RouterOS settings`, `Network collector` и список
`Profiles`; клик по любому из них показывает в основной области только этот раздел.

- Поля записи меняются в зависимости от типа: `A` показывает `address`, `FWD` — `forward-to`.
- Переопределения профиля отмечают каждое поле, отличающееся от глобального значения, и
  предлагают сброс к нему одним кликом.
- У поля пароля есть переключатель показать/скрыть.
- Закреплённая панель сохранения содержит обе кнопки сохранения, строку статуса и метку
  несохранённых изменений.

### Панель DevTools

Тот же визуальный стиль, что и в popup: единая панель инструментов, переключатель
`Domain / Host`, поиск, счётчик выбранного и общий блок результата. Все строки локализуются
через `_locales`.

Все поверхности следуют светлой/тёмной теме браузера/системы через CSS
`prefers-color-scheme`.

### Профили

- Несколько профилей RouterOS.
- Последний успешно использованный профиль пробуется первым.
- Identity можно получить через `/rest/system/identity` или ввести вручную.
- Поддержка копирования профиля.
- Переопределения на уровне профиля:
  - тип DNS-записи: `FWD` / `A`
  - `address`
  - `forward-to`
  - `address-list`
  - `comment`
  - `match-subdomain`
  - обрезка до базового домена по умолчанию
  - выполнение `:resolve` после добавления
  - сервер `:resolve` (по умолчанию `127.0.0.1`)
  - таймаут запроса

### Определение роутера

Порядок определения:

1. Пробуется последний успешно использованный профиль.
2. Если IP недоступен, истёк таймаут или соединение отклонено, продолжается перебор
   сохранённых профилей с тем же IP.
3. Если ни один профиль на этом IP не работает, перебираются профили с другими
   IP-адресами.
4. Если соединение успешно, но авторизация не прошла, пробуются другие сохранённые профили
   с тем же IP.
5. Если авторизация успешна, запрашивается `/rest/system/identity`.
6. Если identity совпадает с профилем, используется этот профиль.
7. Если identity отличается:
   - выполняется поиск другого сохранённого профиля с тем же URL/логином/паролем и
     обнаруженным identity;
   - если найден, происходит переключение на этот профиль;
   - если не найден, предлагается создать новый профиль с предзаполненными полями;
   - также предлагается обновить identity в найденном профиле, с явным подтверждением.
8. Если ни одна сохранённая комбинация IP/логин/пароль не подходит, сообщается, что
   сохранённый роутер не обнаружен.

### Сборщик сетевых доменов

Использует `chrome.webRequest`.

Фильтры по умолчанию:

Включены:

- HTTP 4xx
- HTTP 5xx
- `ERR_CONNECTION_REFUSED`
- запрос в ожидании без заголовков ответа дольше 5000 мс

Отключены:

- HTTP 2xx
- HTTP 3xx

Список фильтров редактируется в настройках. Popup использует эти значения по умолчанию, но
пользователь может динамически включать/отключать фильтры в popup, не меняя сохранённые
значения по умолчанию.

`pending without data` означает, что заголовки ответа не были получены через `webRequest`.
Расширения браузера не могут читать необработанные данные сокета.

### i18n (локализация)

Добавлена структура локализации расширения:

```text
_locales/en/messages.json
_locales/ru/messages.json
```

Браузер выбирает язык автоматически. Новые переводы можно добавить, создав ещё один
`_locales/<locale>/messages.json`.


## Определение базового домена

Переключатель `Домен` / `Хост` определяет, сводится ли захваченный хост к регистрируемому
домену перед добавлением. Для этого используется встроенная копия
[Public Suffix List](https://publicsuffix.org/): `a.b.example.co.uk` превращается в
`example.co.uk`, а не в `co.uk`, и корректно обрабатываются частные суффиксы вроде
`github.io`. IP-адреса, `localhost` и хосты, которые сами являются публичным суффиксом,
остаются без изменений.

Список — статические данные в `public-suffix-list.js`, во время работы ничего не
загружается. Обновляется командой `npm run update:psl`.

Режим `Хост` добавляет точное имя хоста и безопаснее, если у записи включён
`match-subdomain`.

## Поведение :resolve при match-subdomain

Начиная с v0.6.1, `:resolve` использует точные хосты, захваченные из текущей вкладки.

Если у действующей DNS-записи включён `match-subdomain`, расширение выполняет resolve для:

- самого добавленного домена;
- каждого захваченного хоста из текущей вкладки, совпадающего с добавленным доменом;
- каждого захваченного хоста из текущей вкладки, оканчивающегося на `.` + добавленный домен.

Пример:

Добавленный домен:

```text
example.com
```

Захваченные хосты:

```text
example.com
api.example.com
cdn.static.example.com
other.net
```

RouterOS получит `:resolve` для:

```text
example.com
api.example.com
cdn.static.example.com
```

Если `match-subdomain` отключён, resolve выполняется только для явно добавленных доменов.

## Требования к RouterOS

REST API RouterOS должен быть включён через `www` или `www-ssl`.

Рекомендуемая минимальная настройка:

```routeros
/ip service enable www-ssl
/ip service set www-ssl address=192.168.0.0/16
/ip dns set allow-remote-requests=yes
```

Используйте отдельного пользователя RouterOS.

## Ограничения браузера

Расширение не может напрямую прочитать шлюз по умолчанию Windows, SSID или имя сетевого
профиля. Оно может только перебирать сохранённые URL-адреса RouterOS и определять роутеры
по `/rest/system/identity`.

Расширение также не может напрямую отправлять UDP DNS-запросы. Оно инициирует DNS resolve
через REST RouterOS:

```routeros
:resolve "example.com" server=127.0.0.1
```

`server=` обязателен: без него RouterOS выполняет resolve через собственный клиентский
resolver, и статическая DNS-запись (и её `address-list`) никогда не заполняется. Сервер
настраивается глобально и на уровне профиля; по умолчанию используется `127.0.0.1`, то есть
собственный DNS-сервер роутера.

При использовании HTTPS с самоподписанным сертификатом RouterOS браузер может блокировать
`fetch`. Используйте доверенный сертификат, примите сертификат вручную в браузере, если это
возможно, либо используйте HTTP только в доверенной локальной сети.

## Разрешения

Разрешения манифеста и обоснование каждого из них:

- `activeTab` / `tabs` — чтение URL и хоста текущей вкладки, чтобы popup и панель devtools
  могли предзаполнить добавляемый домен, а сборщик сетевых доменов — группировать
  захваченные запросы по вкладке, из которой они были сделаны.
- `webRequest` — наблюдение за URL, хостами и кодами статуса исходящих запросов для
  сборщика сетевых доменов. Расширение читает только метаданные запроса и никогда не
  читает и не изменяет тело запроса или ответа.
- `storage` — сохранение профилей RouterOS (URL, логин, пароль, значения DNS по умолчанию
  для профиля) и настроек расширения на этом устройстве через `chrome.storage.local`, а
  также хранение метаданных захваченных запросов в `chrome.storage.session`, чтобы они
  переживали выгрузку service worker. Ничего не синхронизируется через учётную запись
  браузера, пароли хранятся без шифрования — см. [PRIVACY.ru.md](PRIVACY.ru.md).
- Разрешения на хосты (`http://*/*`, `https://*/*`, `ws://*/*`, `wss://*/*`) — расширение
  обращается напрямую к устройству RouterOS, которое настраивает пользователь; это может
  быть любой LAN- или WAN-адрес, поэтому разрешение невозможно сузить до фиксированного
  источника. Эти разрешения также необходимы, чтобы `webRequest` мог наблюдать за запросами
  на страницах, которые посещает пользователь.

Из браузера не уходят никакие данные, кроме запросов, которые расширение делает напрямую к
настроенным пользователем эндпоинтам REST API RouterOS. Подробности см. в
[PRIVACY.ru.md](PRIVACY.ru.md).

## Повторное добавление домена

Добавление идемпотентно. Перед записью расширение один раз за пакет читает список
статических DNS-записей роутера и затем для каждого домена:

- создаёт запись, если записи с таким именем нет;
- обновляет существующую запись (`PATCH`), если она есть, но отличается;
- ничего не делает, если эквивалентная запись уже есть.

В результатах указано, что именно произошло с каждым доменом, и сколько ещё записей с тем же
именем уже есть на роутере — например, дубликатов, оставшихся от прежних версий. Они
показываются, но не удаляются: удалите их сами, если нужно.

## Разработка

```bash
npm ci
npm run lint            # eslint
npm test                # node --test, без дополнительных зависимостей
npm run validate:manifest
npm run build           # распакованное расширение в dist/wdrosdns
npm run update:psl      # обновление встроенного Public Suffix List
```

Список упаковываемых файлов вычисляется из `manifest.json` и графа ссылок HTML/JS, поэтому
новый модуль попадает в сборку автоматически. CI собирает и проверяет ZIP при каждом пуше;
workflow релиза дополнительно требует совпадения версий git-тега, `manifest.json` и
`package.json`.

## Установка

### Из Chrome Web Store

[MikroTik DNS Helper](https://chromewebstore.google.com/detail/mikrotik-dns-helper/mkiocapbghnhoaahkgepodgkmfjnofcg)
— рекомендуемый способ, с автоматическими обновлениями. Страница расширения работает в Chrome
и в Edge (откройте её в Edge и разрешите установку расширений из сторонних магазинов).

### Из ZIP-архива релиза

1. Распакуйте архив.
2. Откройте `edge://extensions/`.
3. Включите режим разработчика.
4. Нажмите «Load unpacked» (загрузить распакованное расширение).
5. Выберите распакованную папку, а не zip-файл.
